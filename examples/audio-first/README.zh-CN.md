# 离线音频优先剪辑教程

[English](README.md)

用两段原创合成音、一张纯色底图和三条字幕制作六秒钟的可编辑短片。本例用于学习音频剪辑，不是成品音乐，也不是语音识别演示。运行仅使用本机 HTTP/MCP，不访问外部网络服务、不下载模型、不读取个人素材库。

## 运行

准备源码环境、[开发依赖](../../CONTRIBUTING.zh-CN.md)、FFmpeg/ffprobe 和构建后的 Web 编辑器。在仓库根目录、已激活的 Python 环境中执行：

```sh
python examples/audio-first/demo.py --output .artifacts/audio-first-01
cutvoke serve --data .artifacts/audio-first-01/data
```

每次使用**新目录**。已有目录即使只保存了一部分失败结果也会被拒绝，请保留证据并换一个名字。打开 `serve` 打印的网址，选择 **Audio first · editable tutorial** 工程。保留整个工程目录，而不只是数据库。`result.json` 给出相对运行目录的成片和工程包路径。

## 操作与验证

1. 先建立独立工程，再使用 `projectId` 导入素材，保证素材库与时间线属于同一个工程。
2. 用 Python 合成低音量双音背景和短提示音，使用工程范围的素材接口明确标记为 `music`、`sound_effect`。分类只帮助整理素材，不改变混音，也不根据文件名猜测用途。
3. 获取真实源文件波形 PNG 和试听流，验证流与源文件字节一致。源波形不包含时间线音量、淡入淡出或其他音轨。
4. 先 `command_preview`，再在短时编辑租约下提交一次带修订检查的 `edit.batch`。背景音量为 0.6，首尾各淡化 0.8 秒；2–3 秒的提示音音量为 0.4，也有短淡入淡出。三条字幕仍可编辑，交接前释放租约。
5. 生成实际预览帧，并用 `preview_audio` 获取提示音附近两秒的合成混音片段。`mix-audition.wav` 包含时间线混音，区别于源文件试听。
6. 通过 `export.enqueue` 导出，核对媒体流和时长、完整解码，测量非静音、无削波，以及首尾 RMS 小于稳定中段的 30%。同时核对 880 Hz 提示音只出现在指定区间。这些是客观数值检查，不能替代主观听感评价。
7. 打包工程并解包到另一个新目录，核对可编辑时间线（忽略重定位后的素材路径），再次导出，逐字节比较解码后的 PCM 音频。

## 人工编辑器检查

脚本不会模拟这些人工检查或声称它们已通过。试听前先调低播放音量。

- 在素材库检查背景音乐、音效分类和波形，分别试听原素材。
- 打开时间线，播放经过第 2 秒的提示音，听首尾淡化，同时观察实际画面，不只看时间指针。
- 选择字幕“A small cue”，修改并保存，确认时间区间不变且预览更新；撤销一次检查恢复。
- 检查音频片段的音量和淡化控制，修改背景音量、预览后撤销，原始合成文件应保持不变。
- 单独查看解包后的工程时，先停止原服务，再运行：

```sh
cutvoke serve --data .artifacts/audio-first-01/roundtrip/projects.sqlite
```

打开恢复后的工程，检查字幕、两个音频片段及播放。工程包格式可能不保存旧式恢复素材库中的用途分类；脚本核对的是可编辑时间线及音量/淡化，不能将它称为全素材库备份。

## 输出与来源

`result.json` 是客观检查结果，`calls.json` 是本机 MCP 操作记录。`frames/` 保存三个实际画面和两张源波形；`mix-audition.wav` 是片段而非完整成片；`roundtrip/` 是独立解包的工程。媒体、数据库和日志都放在忽略的 `.artifacts/` 中，不要提交到 Git。

音调和纯色卡由本仓库 MIT 许可脚本原创生成。不使用第三方媒体、录音、人声、下载字体或外部服务；字幕渲染可使用 CutVoke 自带字体。公开证据不要替换成私人素材。
