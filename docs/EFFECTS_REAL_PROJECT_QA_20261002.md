## 实际执行的流程

每个预设均通过 `EditService` 应用，执行撤销、重做；有可编辑主控参数的预设修改该参数后再次撤销、重做；关闭数据库、重新打开工程，验证快照保持一致。之后真实生成预览和导出，比较对应时间的帧。

批量案例使用真实工程的两个 2 秒片段，320×180 / 30fps；图片案例使用原始图片；人物案例保留真实透明人物叠加。为分别验证每个预设，清除了源工程目标片段原有的效果和关键帧，再应用待检预设。

612 个贴图逐个验证插入、变换、撤销、重做和持久化。渲染时每组八个独立叠加轨，使用真实工程背景及音乐，640×360 / 30fps / 2 秒，逐项检查画面中有可见像素变化。

低画质 H.264 的预览窗口与整片导出使用不同的编码参考帧，像素可以有压缩差异。64 个预设案例另做无损诊断，对齐帧的平均 RGB 差异低于 0.1，验证差异没有来自效果计算或时间偏移。产品低画质档仍为 CRF 28。

## 发现并修复的问题

### 1. 手持震动、幻影残迹作用于视频后，接后续片段导出失败

真实视频中出现拼接两端像素比例不同的错误，例如 SAR 855:848 与 1:1。原因是裁剪、缩放后保留了变化的 SAR。画布缩放链现统一设置 `setsar=1`，视频拼接和预览回归通过；这两个预设也已随全部 281 案例重跑通过。

### 2. 多贴图的短预览偶发停在首帧

本机 FFmpeg 9.0.1 在复杂图片叠加图被短窗口截断时偶发持续输出 frame=0、输出文件不增长、CPU 不再消耗。同一工程的完整导出可成功。单独改变线程数和编码参数没有可靠消除此现象。

背景编码现禁用交互式 stdin。Windows 预览同时检查 CPU 工作量和文件增长，持续八秒没有进展时终止停滞进程。总长不超过八秒的预览工程采用有限长度无损中间文件恢复，再提取请求窗口；中间文件自动清理。较长工程仍采用一次有界重试。进行中的高负载计算会更新 CPU 计时，不会仅因耗时长而触发恢复。

最终 77 组贴图渲染有四组实际触发恢复，均成功完成。回归测试主动注入停滞，验证终止旧进程、恢复预览、24 帧时长、音轨存在、中间文件清理，以及无损模式下恢复前后的全部视频帧完全一致。

FFmpeg 偶发停滞的底层原因尚未确定。此项修复的证据是检测和恢复成功；恢复期间仍会增加等待时间。

### 3. 撤销记录耗尽后应用特效，撤销按钮仍禁用

统一命令入口现在在非历史命令成功改变工程版本后恢复撤销状态、清除旧历史提示，并关闭旧重做状态。网页已复现旧条件，验证修复后再次应用效果能够撤销和重做，刷新后效果保留。
