# 打开工程时准备完整预览

## 用户流程

打开工程后立即显示全屏加载页。工作区在其下方挂载，但处于 inert 状态；快捷键和鼠标不能提前开始播放或修改工程。

| 阶段 | 放行条件 |
| --- | --- |
| 读取工程 | 当前工程 JSON 已读取，旧工程响应不会覆盖新选择 |
| 准备预览 | 全部可播放的 8 秒窗口完成，连续 MP4 合成和媒体检查通过 |
| 加载画面 | 浏览器完整加载 MP4，实际解码首帧并达到 canplay 状态 |
| 进入编辑器 | 首帧可显示后关闭全屏页，点击播放可直接播放 |

进度来自已完成窗口数和实际准备阶段，没有倒计时或虚构 ETA。空工程直接进入编辑器。错误时保留全屏页，提供重试、返回工程列表和进入工程修复；不会把失败的准备当成正常完成。

## 实现

- 后端 `PreviewPreparation` 持有不可变工程快照，单个后台工作线程控制生成并发。调用现有窗口渲染，及时保留窗口文件，避免原来 8 个窗口的缓存容量限制破坏长工程准备。
- 窗口合成连续文件，统一音频格式、补齐静音窗口，保留精确视频时间戳；完整预览最长边为 960 像素，保持画幅比例。工程与导出仍使用原分辨率。
- 成功结果原子发布；缓存身份包含渲染版本、序列及嵌套内容和素材文件大小/修改时间。项目名称、版本号和字幕修改不单独触发基础视频再生成。
- 前端完整读取连续文件为 Blob，再交给同一个播放器元素。播放过程中无需请求下一段视频，也不会在每个 8 秒边界换播放器。
- 修改画面或音频后，播放器使用原来的局部分段更新路径，避免每次小编辑都重新阻塞整个工程。重新打开工程时再次准备最新的完整预览。
- 返回列表、重试和切换工程会取消各自的任务；提交请求仍等待返回任务 ID，从而能取消已经提交而尚未收到响应的任务。对象 URL 在换工程或替换预览时释放。
- 新前端遇到旧服务缺少准备接口时保留原分段预览，并在状态栏提示重启服务。

### API

| 路由 | 用途 |
| --- | --- |
| `POST /api/v1/projects/{id}/preview-jobs` | 提交准备任务，可带 revision，拒绝过期快照 |
| `GET /api/v1/preview-jobs/{id}` | 阶段、已完成窗口、总窗口、进度和错误 |
| `POST /api/v1/preview-jobs/{id}/cancel` | 取消本次准备 |
| `GET /api/v1/preview-jobs/{id}/media` | 仅成功任务可读取连续预览，支持原有媒体 Range 服务 |
| `GET /api/v1/runtime` | `previewPreparation.supported` 标识后台支持情况 |

## 验证结果

使用原始数据库的在线副本测试“潮汐藏馆｜原始可编辑工程”，40 秒、13 个片段、4 处转场。原始数据库的 7 个工程没有修改。

- 完全冷缓存准备约 92.8 秒；复用已有窗口、合成最终 960×540 预览约 3.7 秒；复用完整预览进入约 0.97 秒。
- 最终连续预览 40.000 秒、960×540、含音频，文件约 3.30 MB。
- 点击播放到原生 playing 约 47.5 毫秒。完整播放 40 秒期间，waiting/stalled 为 0，媒体错误为 0，只使用一个视频 URL。
- 8/16/24/32 秒转场附近分别采样 17/17/17/18 次，空画面和黑帧均为 0。加载页、实际播放画面及手机宽度错误页均做了视觉检查。
- 空工程、缺失素材、重试、进入修复、准备时空格快捷键、提交响应延迟时返回取消、旧服务兼容已通过真实浏览器检查。390 像素视口没有横向溢出。
- 新增 4 项回归通过，覆盖缓存身份、取消、HTTP 过期版本/失败媒体和 12 窗口合成；原预览窗口 13 项及 4 个子测试通过。12 窗口即使只保留两个中间窗口，也能合成 96 秒、2880 帧完整视频。
- TypeScript 检查和 Vite 构建通过。Web 重启脚本通过 PowerShell 语法检查和只读检查。

证据位于 `output/playwright/project-opening-20261003/`：`cold-result.json`、`final-result.json`、`light-result.json`、`cases-result.json`、截图、隔离数据库和媒体文件。

### 验收边界

首次生成复杂工程仍需要实际渲染时间，本次全屏准备将这段等待集中到打开工程阶段。缓存等待和转场空画面已经消除；Chrome 自动化仍报告一定数量的呈现掉帧（完整采样 71/1200，轻量采样约 27/379），帧率稳定性需要单独继续分析，不能宣称所有播放性能问题均已解决。一次实验性的编辑器时钟节流未显示改善，已撤回。

完整媒体通过 Blob 加载，浏览器内存使用随预览文件大小增加；离开/换工程时会释放该对象 URL。很长或复杂的工程首次准备时间、完整预览缓存的磁盘保留策略仍可继续优化。

## 启用

前端构建已发布到 `web/dist`，经过检查的原工程连续预览已放入原服务的可再生成缓存目录。后台新增接口需要重新启动服务。

双击仓库根目录 `restart-cutvoke-web.cmd`。启动器先检查运行实例、活动导出并备份数据库，再重启 Web 服务、核对源代码版本和工程内容。完成后刷新浏览器即可，Codex 和 MCP 可以保持打开。

后台是否已生效必须以 `runtime.previewPreparation.supported === true` 为准。
