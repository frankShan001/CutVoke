# 外部 Agent 剪辑能力补齐与客户端验收

日期：2026-10-05。桌面版本：0.3.0。

## 已补齐的能力

编辑器执行确定的剪辑操作，外部 Agent 负责理解需求和判断画面。本次没有添加大模型、聊天或自动生成视频服务。

| 原有缺口 | 本次实现 | 验收 |
| --- | --- | --- |
| Agent 不便寻找工程、制作不同版本 | 分页搜索工程、按版本复制工程 | 复制“潮汐藏馆”真实工程，原工程内容未变化 |
| 无完整素材导入与检查流程 | 本机素材导入、内容去重、素材查询、音视频信息检查；返回可直接插入的 assetId | 导入真实图片和音乐，持久化后插入时间线 |
| 操作参数与预设不便按需发现 | 分页查询编辑命令、按类型搜索预设 | 客户端查询转场预设、批量编辑参数 |
| Agent 无法直接查看实际画面 | 素材/工程多时间点截图，MCP 原生 PNG 图片内容；含标题与字幕 | 查看原工程五个时间点及剪辑结果三个时间点 |
| 导出容易因长调用、重试或服务切换出错 | 异步预览、任务查询/取消、持久化导出历史；稳定命令 ID 防重复导出；提交时固定版本快照 | 实际导出六秒视频；重复提交、过期版本、跨服务取消、重启后查询均有回归覆盖 |
| 人工接手与可编辑交接不完整 | 查询修改事件、编辑租约、批量操作一次撤销、携素材工程包 | 释放租约并生成可编辑工程包，验证撤销/重做和重新读取 |
| 安装版处理中文 MCP 输入异常 | stdio 显式 UTF-8 | 独立客户端调用冻结引擎，中文工程名、标题和字幕通过 |
| Windows 预览明显丢帧 | 减少播放时钟引起的界面更新；采用保留 GPU 的兼容显示合成路径 | 原工程整段播放对比，见下 |
| 复杂路径蒙版渲染失败/过慢 | 平衡表达式树，静态图片的自由路径蒙版计算一次，限制渲染线程开销 | 真实像素透明度、预览/导出一致性、编辑/撤销/重新打开通过 |
| 编辑界面加载失败时等待页遮住恢复操作 | 加载失败进入修复/重新加载流程 | 浏览器流程回归通过 |

MCP 提供 25 个工具。本次新增 13 个：`project_list`、`project_clone`、`commands_list`、`media_import`、`media_list`、`media_inspect`、`resources_list`、`preview_frames`、`preview_prepare`、`preview_job`、`export_job`、`project_events`、`project_package`。HTTP 与 MCP 使用同一实现。

## 真实工程与播放测量

对象：“潮汐藏馆｜原始可编辑工程”，40 秒、30 fps，连续预览为 960×540。

| 显示配置 | 视频帧数 | 丢帧 | 缓冲事件 |
| --- | ---: | ---: | ---: |
| 原 GPU 路径普通播放 | 1200 | 84（7.0%） | 0 |
| 关闭视频叠层 | 1196 | 69 | 0 |
| 仅软件解码 | 1196 | 67 | 0 |
| 软件显示合成 | 1196 | 0 | 0 |
| 保留 GPU 的兼容合成路径 | 1196 | 4（0.33%） | 0 |
| 最终安装版默认配置 | 1196 | 3（0.25%） | 0 |

正式 Windows 客户端默认采用兼容合成路径。最终安装版另一次整段测量为 3 帧丢帧、0 播放错误。主线程采样没有长任务，独立视频窗口也复现原路径丢帧。该结果支持将问题定位到本机显示合成路径；不代表所有显卡和工程均零丢帧。

安装版往返定位 19 秒 → 3 秒 → 19 秒分别为 112、117、34 毫秒，没有新增预览窗口或定位帧渲染请求。记录为 `installed-playback.json` 和 `installed-seeks.json`。客户端已停在原工程第 19 秒。

四处转场前后逐帧采样未发现意外黑帧；标题在真实视频帧中可见。诊断记录在 `output/playwright/agent-workflow-20261005/`，包括 `native-playback.json`、`native-ordinary.json`、`gpu-compatible-playback.json` 与性能采样文件。

Windows 诊断时可用环境变量 `CUTVOKE_DIRECT_COMPOSITION=1` 恢复系统默认合成路径。该选项不改变系统驱动或工程内容。兼容路径的底层开关对应 Chromium 的 [DirectComposition 实现](https://chromium.googlesource.com/chromium/src.git/+/8b22453afaafdc1b390bf31c9bd29e3a45e70e5d/ui/gl/direct_composition_support.cc)。

## 使用与边界

操作顺序与准确参数示例见 [外部 Agent 剪辑接入](external-agent-editing.md)。旧 MCP 进程不会自动替换已加载的代码；客户端重新连接后才能发现新增工具。独立新连接已经通过上述实际剪辑验收。

这次完成常用剪辑闭环及已发现问题的修复。更多机型、多小时工程与更大素材量仍需要持续实测，不能从这个四十秒工程推导所有项目的性能。
