# 快速拖动播放头的预览错误修复

日期：2026-10-03。工程：潮汐藏馆｜原始可编辑工程，40 秒、13 个片段、3 个轨道，revision 4。

## 复现与原因

- 在工程副本的分段视频预览中，24 次快速定位发出了 24 个单帧请求及大量视频段请求。多数单帧请求随后取消，但服务端已开始的渲染不因此停止。此次实际拖动观察到长时间加载，未自然出现 Failed to fetch。
- 对同一真实工程注入短暂网络失败后，原版停在“预览不可用 / 预览渲染失败：Failed to fetch”，与用户截图一致。
- 视频错误回调没有校验当前视频元素及来源；取消和旧来源的错误可能误触发图片降级。
- 单帧降级只按 300 ms 节流，没有限制在途请求，也没有自动恢复短暂网络失败。
- 图片降级后，每次跨越预览视频段都会重新尝试视频模式，取消当前图片请求。拖动可形成反复降级及多次服务端渲染。

## 修改

1. 标尺和播放头记录拖动状态。播放头位置立即更新；分段预览等待 80 ms 的停顿再定位，松手立即提交准确位置。完整本地预览文件仍使用原生视频定位。
2. 播放中拖动暂时暂停解码，阻止旧 timeupdate 覆盖用户位置；松手后按此前播放意图继续播放。
3. 首帧图片请求等待 100 ms，取消尚未开始的过时请求。
4. 图片降级同时只保留一个在途请求及一个最新目标。暂停拖动后的过时图片及错误均不覆盖最新位置；降级播放仍可显示已完成的采样帧。
5. 取消单独分类；网络错误、408、429 和 5xx 最多额外重试两次。重试期间保留已有可用画面。素材缺失等永久错误继续显示修复提示。
6. 只有当前视频来源的真实错误触发降级，MEDIA_ERR_ABORTED 不触发降级；迟到的旧视频结束事件也忽略。
7. 只有工程内容、工程身份或素材恢复改变时自动重试视频模式。时间线定位不再反复退出图片降级模式。

## 验证

使用 Playwright CLI 操作 Chrome；工程编辑数据使用 SQLite 副本。另用独立浏览器对当前 8787 服务打开原工程作只读验证。

- TypeScript `npm run typecheck` 通过；Vite 生产构建通过。
- 副本：24 次快速定位后只请求 1 个视频段、1–2 张单帧图片（可能包含打开时尚未结束的首帧请求）；最终播放头 19 秒，视频段内时间 3 秒，没有错误页。
- 模拟旧视频迟到错误和当前视频取消错误：保持视频模式，没有错误页。
- 模拟连续两次网络失败：第 3 次自动恢复，没有展示错误页。
- 慢单帧响应下连续拖动：在途图片请求峰值为 1，只保留最新目标。最终显示 PNG 与直接渲染的 19 秒 PNG 的 SHA-256 完全一致。
- 完整预览：快速拖动复用同一 Blob 视频文件，定位到 19 秒；播放中拖动后从 12 秒继续播放。
- 素材缺失：保留文件路径及“重新链接”提示；没有对 422 进行反复重试。
- 本机 8787 原工程：3 轮、每轮 24 次快速定位，没有错误页；松手后定位准确。分段模式播放中跨段拖动也继续播放，未出现错误页。
- 原始数据库 7 个工程内容、revision 和保存数据校验值不变：`34eebb6eefedd9c6bd5ecb3058e97861fce956ee3409a676ba8a96834294cf43`。

证据：`output/playwright/fast-scrub-20261003/` 中的 `fixed-result.json`、`permanent-result.json`、`production-result.json`、浏览器脚本及截图。
