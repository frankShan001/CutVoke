# 往返定位已预览片段的缓存复用

日期：2026-10-04。真实工程：潮汐藏馆｜原始可编辑工程，revision 4，40 秒、5 个基础视频窗口。

## 原因及修复

修复前，返回已访问片段的三次检测没有重新下载视频，但播放器 DOM 每次都被销毁再创建。重新解码耗时 285–332 ms，同时立即显示加载提示。因此本次复现是浏览器缓存数据与播放器解码状态之间缺少复用。

新增两级复用：

- 已下载的完整视频段保存为 Blob，单个工程的画面内容不变时，往返定位共享相同文件和在途下载。
- 保留最近访问的视频元素，暂停并隐藏非当前播放器。再次返回时复用同一个元素、原有缓冲和解码状态。仅当前播放器的事件可以推进播放头。
- 播放器最多保留 8 个元素，并以 64 MiB 的已编码文件总量作为淘汰预算。完整文件缓存以 128 MiB、64 个窗口为预算，优先淘汰最久未使用且未被占用的项目；当前在用片段受保护。即使播放器被淘汰，已编码文件仍可复用。
- 下载并发最多为 2。过时的排队请求不再启动；已经开始的下载完成后进入缓存。切换工程、改变画面内容或恢复素材时释放旧缓存。缓存作用域使用完整画面内容，字幕叠层和工程名称不单独触发失效。
- 准确定位并解码后才结束准备状态。快速缓存命中不立即弹出加载提示；真正超过 200 ms 的等待仍显示提示。新画面未呈现前保留上一张有效画面。
- 下一段预加载完整视频文件。原来的完整工程预览流程继续使用一个连续视频文件。

相关实现：`previewSegmentCache.ts`、`usePreviewSegments.ts`、`PreviewVideoPool.tsx`、`useVideoHandoff.ts` 和 `Player.tsx`。
