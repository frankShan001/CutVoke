# 素材导入与文件夹恢复

在“创作资源”的素材或音乐区域点击“导入文件”，可多选文件。导入进度显示当前文件名、已传/总 MiB 和整批完成数。“取消当前及后续上传”中断尚在上传的文件，并停止后续队列；已经成功入库的素材保留。

Web 导入和上传式重新链接默认接受单文件至 16 GiB，与 JSON 控制请求的 16 MiB 上限分开。媒体以不超过 1 MiB 的块写入临时文件，不先把完整视频读进服务器内存；最多同时接收两个上传。每次读取的空闲超时为 30 秒。上传中断和取消会清理临时文件，服务重启也会回收已退出进程留下的上传分片，不删除其他活跃进程正在写的文件。

需要调整媒体上限时，在启动服务/桌面客户端前配置 `CUTVOKE_MAX_MEDIA_BYTES`，值为正整数字节数。例如 PowerShell：

```powershell
$env:CUTVOKE_MAX_MEDIA_BYTES = '34359738368' # 32 GiB
cutvoke serve
```

上限不是可用磁盘容量的承诺；接收前会检查剩余空间。JSON 请求仍有独立的小请求限制。导入使用本机上传接口，改变上限不会扩大浏览器对任意本地路径的访问权限。

## 文件夹级重新链接

当已登记的用户素材文件丢失时，展开“从文件夹批量重新链接”，选择保留了原文件的目录。

1. **扫描预览。** 浏览器仅提交相对路径和文件大小清单。服务按原相对路径/名称与大小查找候选，列出缺失项；同名、同大小的多个候选明确标记歧义，需要手动选择。
2. **核对候选。** 可查看文件路径、原始时长和画面尺寸，并在本地预览候选图像或试听视频/音频。该步骤不会修改工程，也不会上传整个文件夹。
3. **确认恢复。** 点击“恢复已确认的 N 个素材”。只上传勾选的候选，按原 assetId 恢复到原素材路径。原工程、源入点、时长、效果、保存版本和撤销历史不被改写。

新版导入会同时记录内容 SHA-256 和原相对路径。恢复这些素材时，服务器重新计算上传内容指纹；即使名称与大小相同，内容不同也会被拒绝，不会错误接回工程。旧版 MCP 的内容寻址 assetId 也可作为原始指纹。

旧版 Web 导入的素材可能没有原始指纹。这类候选默认不勾选，必须逐项选择、预览并勾选“已人工核对该候选，确认恢复”，才可以一起应用。服务器仍核对文件大小、媒体类型、时长和画面规格；它不能替代人工确认旧素材的内容身份。恢复成功后会补记新的内容指纹。

丢失项没有候选时应另选目录；候选不符合原大小或元数据时保持缺失并显示错误。恢复期间同样可取消当前上传与后续队列，已经完成的恢复保留。

单个素材也保留原有“重新链接”入口，支持真实上传字节进度和取消。素材探测的时长在内部保留原始精度，例如 1.860 秒不会先舍入成 1.9 秒；列表显示的小数位只是展示格式。向视频时间线插入时按工程帧率选择合法帧边界。
