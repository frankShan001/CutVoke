# 界面翻译贡献

[English](translations.md) · **简体中文**

CutVoke 的 Web 编辑器和自有桌面壳层提供 `zh-CN`、`zh-TW`、`en`、`ja`、`ko`、`es`、`fr`、`de`、`pt-BR`、`ru`、`ar` 界面语言。翻译范围包括标签、帮助、菜单、校验和操作提示，不改写工程名称、字幕正文、素材文件名、ID、命令值或工程序列化数据。

## 当前审校状态

英文词库按现有行为整理；繁体中文以 OpenCC 转换为起点并调整专案术语；其他语言由本机离线 M2M-100 初稿起步，修正了高频控件和术语。模型和工具不随产品分发，也不是运行依赖。初稿在本机生成，没有把源码文案发送到翻译服务。[公开模型说明](https://huggingface.co/jncraton/m2m100_418M-ct2-int8) 标明 MIT 许可证和上游模型。

**本轮任何语言均尚未经母语使用者审校。** 长篇说明尤其可能需要更地道的措辞。词库覆盖和浏览器检查验证技术行为，不等同语言准确性认证。欢迎注明语言与具体界面提出修正；只有真实审校者和明确范围才可记录为已审校。

## 新增或修正文案

词库位于 [`web/app/src/i18n/locales/`](../../web/app/src/i18n/locales/)，以源码中的简体中文文案作为消息键：

```tsx
tr("已导入 {0} 条字幕", count)
```

对应英文为 `"Imported {0} captions"`。每个数字占位符的拼写及出现次数必须与源消息一致，可按语法重排。用户内容只通过参数传入，**不能调用 `tr(project.name)` 或 `tr(caption.text)`**。新增文案优先使用完整句子，避免拼接翻译片段。

修改源码后在 `web/app` 运行：

```bash
npm run i18n:extract
npm run i18n:check
npm run test:i18n
npm run typecheck
npm run build
```

提取器从字面量 `tr()`、`msg()` 调用更新 `zh-CN.json`。为其他词库同步添加真实翻译，删除过期键，再运行校验。不能把英文复制到缺词位置并据此宣称完成语言支持；产品名、ID、公式和通用技术术语可合理保持一致。

保存到状态中的提示使用 `msg(source, ...values)`，显示时调用 `formatMessage(message, locale)`，让已有提示也跟随语言切换。这些描述对象只属于界面状态；用户正文保持普通字符串，绝不能拿它查询词库。

显示翻译的组件使用 `useLocale()`，包括经过 memo 的组件。模块顶层界面表使用 getter，使标签随切换更新；产生翻译文案的 memo 依赖 locale。不要让切换语言触发工程保存或重置用户草稿的 effect。

## 语言匹配、保存与回退

`src/i18n/locale.ts` 按 `navigator.languages` 顺序匹配。中文 Hant/TW/HK/MO 变体使用繁体中文，其他中文变体使用简体中文；葡语变体匹配 `pt-BR`，其他支持的基础语言匹配地区标签；不支持的偏好回退英语。

选择器含“跟随系统”。Web 偏好使用 `localStorage["cutvoke.ui.language"]`，存储受限时仍可在当前会话选择；storage 事件同步标签页。根节点 `lang`、`dir` 与生效语言一致。缺少界面译文时先回退英语，再回退源码文案，插入的用户数据保持原值。

桌面壳层在 Electron 用户数据目录的 `ui-language.json` 中仅保存 `{preference}`。预加载脚本在 Web 编辑器启动前提供该偏好，因此本地服务端口改变不会丢失选择；“跟随系统”读取 Electron 的系统语言偏好。语言 IPC 仅限本窗口主框架，写入时还校验本地加载页或服务来源。这些配置与工程数据分开保存。

桌面词库位于 [`desktop/locales/`](../../desktop/locales/)，由 [`desktop/i18n.cjs`](../../desktop/i18n.cjs) 加载；各语言保持键及编号占位符一致。加载页、缓存目录标题和确认按钮、启动错误及服务退出摘要均使用这些词库。目前没有自有原生应用菜单；Web 工具栏和右键菜单使用 Web 词库。文件列表、系统提供的取消按钮等原生控件跟随操作系统语言。

## 效果与资源

效果请求携带界面 `lang`，现有注册表按 `name`、`description` 语言映射返回元数据，并回退英语。贡献清单使用相同语言代码；[柔和揭幕样例](../../effects/transitions/cutvoke.transition.community.soft-reveal/manifest.json) 已含所有支持语言。注册表按进程缓存，修改清单后需重启服务。

`effectId`、参数名、枚举值、分类和细分类键保持稳定。已知分类键有独立显示标签，未知贡献标签及用户预设按原文显示，因此未翻译的资源元数据可能显示英语；原始诊断信息也保留用于排错。界面语言不会设置语音识别语言，也不会翻译识别正文。

## 浏览器验收

请区分三类内容：

- **自有界面：**控件、加载、校验、操作摘要及 ASR/人物处理进度使用译文。`backendMessages.ts` 枚举音频提取、模型加载、GPU 回退及带设备参数的 SAM2 跟踪；测试会对照 Python 源码检查固定阶段。
- **原始诊断：**第三方库错误、未知服务详情及工程校验细节保留原文，外层使用本地化摘要或原始诊断标签；不要拿自由文本查询翻译字典。预检摘要按稳定问题代码显示，原始详情仍可查看。
- **作者元数据：**预设、贴纸、模板名称、说明、自定义分类和注册表参数说明使用作者提供的语言项，包括随仓库发布的资源。缺失时沿用注册表回退；此项不翻译外部所有资源。

用户创作内容有意保持原值。浏览器验收使用 Windows Chrome；桌面检查运行真实 Windows Electron，使用隔离配置与当前 Web 构建。QA 截图使用软件离屏渲染，原生弹窗参数通过拦截返回值自动检查，因此不代表系统对话框外观、安装包、跨平台或母语验收。

阿拉伯语使用 RTL，侧栏跟随阅读顺序；时间线、时间码、数字控件、素材坐标和播放方向保持 LTR 物理语义。除文字外，也检查布局和键盘顺序，并确认阿拉伯语与拉丁文字混排的用户内容未被修改。

```bash
npm run test:e2e -- e2e/i18n.spec.ts
```

在 `desktop/` 中运行 `npm run test:i18n`，检查所有壳层词库、占位符、持久偏好及原生弹窗参数。Windows 已安装桌面依赖和仓库 Python 环境时，`npm run test:i18n:electron` 运行真实壳层，覆盖德语/阿语加载页、所有语言选择、新端口重启保留偏好、拒绝外来 IPC、真实启动失败及自有服务退出。测试使用独立工程和配置目录，不打开个人工程。QA 专用渲染和运行时选项不改变正常打包启动。

测试使用隔离工程，覆盖系统匹配与刷新保留偏好、所有语言反复切换、工程数据不变，以及中文、英文、德文、阿拉伯语的菜单、弹窗、草稿保留和溢出。新增工作流补充针对性用例；人工检查也应包括较窄窗口、校验与错误、长说明、弹窗内切换、效果元数据回退。不要使用私人工程或未经授权上传截图。
